# Proposed spec changes (candidate v0.5 edits)

Deviations from `sectgrep-spec-v0.4.md` are recorded here as proposals with the evidence that motivated them. Nothing here changes the spec until a human folds it into v0.5. The repository follows the proposal in the meantime so the code and the fixture stay consistent; each row says where.

| # | Spec section | Proposal | Motivation | Where applied | Status |
|---|---|---|---|---|---|
| 1 | B.2 `_source.yaml` | Add `id_template` and optional `anchor_template` next to `id_pattern`, and require `id_pattern` to use named groups. | `id_pattern` says whether a query is citation-shaped but not how to build the Work id and anchor from the match. The citation short-circuit needs both. | `fixtures/corpus/*/_source.yaml`, `proto/sect_proto/corpus.py` | Proposed (milestone 0) |
| 2 | B.2 tree | Non-leaf nodes (title, chapter, subchapter, part) are files with the same front matter and a minimal body. | `parent:` chains must resolve to real ids, and part-level `authority` / `citation` need a home. The spec shows only leaf files. | `fixtures/corpus/cfr-title-99/**` | Proposed (milestone 0) |
| 3 | B.2 versioning | Filename convention for Expressions: current `<file>.md`, prior `<file>@<effective>.md` in the same section directory. | The spec says "new Expression = new file, same id" but not how the files are named. | `fixtures/corpus/cfr-title-99/I/A/2/2.7/` | Proposed (milestone 0) |
| 4 | B.2 notices | Notice files carry an `actions:` list in front matter with the Action record fields from B.2, and the Action id is `<notice id>#instr-<n>`. | B.2 defines the Action record shape but not where it is written before `actions.jsonl` is built. | `fixtures/corpus/fr/2026/2026-00001.md` | Proposed (milestone 0) |
| 5 | E.1 question generation | The CRAwLeR adversarial filter threshold (rank <= 10) is a parameter, defaulting to 10, and the fixture run records the value used. | On a corpus of ~45 chunks rank 10 is the top quarter, which filters almost everything; the threshold is meant for corpora of thousands of sections. | `eval/questions/README.md`, `proto/sect_proto/questions.py` | Proposed (milestone 0) |
| 6 | B.4 lexical | The tantivy text fields (title, path, context, body) use a tokenizer with stopword removal and English stemming; `citations` and `terms_defined` stay exact. | Milestone-0 evidence: with raw tokens, query function words are rare in short boosted fields and get a large IDF, so "Subchapter A" outranks the section a question is about. Locate Recall@5 0.87 raw vs 0.95 with the change; body-only BM25 0.87 vs 0.97 (`eval/results/m0-ablation.md`). | `proto/sect_proto/index.py` | Proposed (milestone 0) |
| 8 | A.2 item 10, H.8, F.1 milestone 0.5 | Remove `zg` (zvec-grep) from the list of "forkable Rust hybrids" and describe it as a TypeScript design reference; keep `semble_rs` on the list with the note that it has no on-disk index. | Milestone 0.5 reading: `zg` is `@zvec/zvec-grep`, a Node 22 TypeScript project with no Cargo manifest, that spawns a managed ripgrep for exact search. See `docs/decisions.md` 15a. | `docs/decisions.md` | Proposed (milestone 0.5) |
| 9 | B.3 `map` | `--scope` accepts `id#anchor`, so `--complete` returns the paragraphs nested under one paragraph; under a section it returns the top-level paragraphs, under a container the whole subtree in document order. | The subtree-completeness questions ("all sub-items of § 2.13(c)") need a paragraph-level scope, and the spec says only "returns a full subtree by traversal". | `crates/sect-struct/src/verbs.rs` | Proposed (milestone 2) |
| 10 | B.4 structural | `xrefs.jsonl` records how each edge was found (`via`: link, prose, front-matter), the body line, and whether it resolved; an unresolved prose citation is a warning, an unresolved link an error. | The spec says unresolved refs are reported by `status` but not how authored links and inferred prose citations are told apart; an agent needs to know which one it is looking at. | `crates/sect-struct/src/graph.rs` | Proposed (milestone 2) |
| 11 | B.4 structural (prose xrefs) | A bare citation (`§ 2.1`, `part 17`) resolves against the document's home title only (its own source, or the base source an overlay or notice targets); a citation into another title must be explicit (`4 CFR 2.1`); `part N of title X` resolves only when X is the home title. | With two titles in one corpus, every title's `id_pattern` matched the same bare `§ 2.1`, producing cross-title edges and "not active at effective date" errors. | `crates/sect-corpus/src/cite.rs` | Proposed (milestone 4) |
| 12 | B.4 lexical | Add a `self_id` field (the chunk's own id components, boost 6) beside `citations`. | Until the milestone-5 citation short-circuit, a citation-shaped query ranked sections that cite `§ 2.8` above `§ 2.8` itself because both carry the same citation token. | `crates/sect-lexical/src/lib.rs` | Proposed (milestone 4) |
| 13 | B.7 versions | `model2vec-rs` is 0.2.1 on crates.io (no 0.3.0 exists); it is built with `fancy-regex` instead of the default oniguruma binding to avoid a C dependency. | Verified 2026-09-03 with `cargo search` and `cargo info`. | `Cargo.toml` | Proposed (milestone 4) |
| 14 | B.4 fusion | With `--include-superseded`, collapse is per Expression rather than per Work, so an older text can appear next to the current one and take the -0.5 penalty. | Collapsing per Work made the penalty unreachable: the superseded Expression was always dropped in favour of the current one. | `crates/sect-query/src/lib.rs` | Proposed (milestone 4) |
| 26 | C.3 born-digital PDF | State the layout rules the C.3 elements need on GPO PDFs: split columns at a vertical gutter before lines are built (tolerating the one or two items that span it); find running heads by isolation (a row of short blocks at the top or bottom of the content with a gap beside it above a line pitch) and bare page numbers near an edge, not by page-edge bands; recover U+FFFD from GPO fonts to section sign and dashes by context; take boldness from the loaded font name. Source `id_pattern` allows four-digit parts. | GPO running heads sit a fifth of the way down the page and alternate between verso and recto, so neither an edge band nor repetition finds them; lines built before columns splice the two columns; Title 29 has four-digit parts (1910, 1926, 4044) that a three-digit pattern cannot match. | `packages/sect-convert/src/elements/pdf.ts`, `src/passes.ts`, `src/ecfr.ts` | Proposed (milestone C1) |
| 25 | C.3 Federal Register parser | A part removed without an AMDPAR (`PART 42—[REMOVED AND RESERVED]` followed by one sentence in REGTEXT) yields one `remove` Action on the part. Bare `Part N` and `§ N.M` mentions in a rule's preamble become explicit links only when the rule's CFR lines name a single title; a multi-title rule keeps them bare (a judgment WS2 must not make). A rule carries one CFR line per title and every line feeds `parts_affected`. | The rescission rule 2026-17726 has no amendatory paragraph at all; a three-title rule (2026-17622) had its Title 29 and 45 sections linked under Title 26 when only the first CFR line was read. | `packages/sect-convert/src/fr.ts` | Proposed (milestone C1) |
| 24 | C.3 OCR (API path) | On the API path the transcriber pair is olmOCR-2 primary and GLM-OCR secondary, both whole-page; divergence is per primary line by an order-independent word alignment rather than a per-line fuzzy match in sequence; olmOCR's metadata block is not page text; both raw readings are kept under `work/<sha>/ocr/`; a page whose secondary is unusable (looping, or a word count far from the primary's) is reported as unverified rather than divergent line by line. | The two models read multi-column scans in different orders and break paragraphs differently, so a sequential line match flagged three lines in four for no textual reason (decisions #39). | `packages/sect-convert/src/ocr/dual.ts`, `src/extract.ts` | Proposed (milestone C1) |
| 23 | B.2 eCFR converter | EFFDNOT and CROSSREF records are written as candidate JSONL under `<corpus>/.work/cfr-title-N/` (`effdnot.jsonl`, `crossref.jsonl`), outside the corpus walk, for WS3 to turn into effective-date and xref facts; the corpus files keep only what the converter can state without judgment. Section `effective` stays the title's snapshot date until the versioner's per-section dates are merged (a C2 item). | B.2 names the records but not where they live; they are candidates, and a hidden directory keeps them out of the index. | `packages/sect-convert/src/cli.ts` | Proposed (milestone C1) |
| 22 | B.2 / C.5 validation | Four validation errors become warnings: an Action target that does not resolve (B.6 lists missing Action targets under lint); a link from a notice that does not resolve; an explicit link whose id prefix no source in the corpus declares; a prose-derived reference whose anchor is not found. A notice's links skip the effective-date activity check. | A notice describes the text before its own amendments (a section it removes, a title the corpus does not hold), and with a snapshot-dated base every notice older than the snapshot failed the activity check; none of these is a contract violation the notice's author can fix. | `crates/sect-corpus/src/validate.rs` | Proposed (milestone C1) |
| 21 | C.3 OCR | Name the transcriber pipelines rather than bare models: primary PaddleOCR-VL-1.5 with its layout stage, secondary olmOCR-2 with its pipeline; a whole-page single-prompt path is reserved for plain born-digital text (GLM-OCR). State the page scale per model (olmOCR 1288 px long side, GLM-OCR 1540, PaddleOCR-VL 1288 or more; floor by DPI, cap 3 MP, never upsample scans) and the repetition guard on any VLM request. Drop MinerU2.5 from the candidate list (AGPL-3.0). | The bake-off showed element-level models loop on whole pages and lose reading order on multi-column scans without their layout stage; the spec's model list and 'VLM only for low-confidence pages' design did not anticipate the pipeline-versus-page distinction. | eval/results/c0.md, decisions #38 | Proposed (milestone C0) |
| 20 | B.4 exact, n-gram prefilter | State the scheme: text is ASCII-lowercased; grams are 4 bytes; a gram at position k is indexed iff the weight of its middle byte pair is a strict local extremum among the three pairs inside it, weights being corpus-wide rarity ranks of byte pairs (ties broken by pair value); postings are file ids in the order of grep's own file walk (every file ignore rules admit, not only sections); required literals come from `regex_syntax`'s extractor, prefixes or suffixes whichever side has the longer shortest literal; a query with no literal, a literal with no gram, or a case-insensitive non-ASCII literal falls back to a full scan; the prefilter is skipped when the index is not fresh. Flags: `sect index --ngram on|off|auto` (auto = at 200 MB and above, `SECT_NGRAM_THRESHOLD_MB`), `grep --no-index`. The layer is rebuilt whole on any change. | The spec names the pieces (pair weights, extractor, roaring postings, mmap table) but not the selection rule, and the rule is what makes the prefilter sound: every pair it consults lies inside the gram, so the grams of a substring are grams of the string. | `crates/sect-ngram`, decisions #6 | Proposed (milestone 3b) |
| 19 | B.3 MCP | Name the toolsets (`seven`, `full`), the HTTP path (`/mcp`), and that tool results carry the CLI text as content and the `--json` value as `structuredContent`; a verb error is an `isError` tool result. State that `sect install` registers `{command, args: [serve, --corpus, <abs>]}` with Claude Code (`claude mcp add` or `.mcp.json`), Claude Desktop, and Cursor, and never publishes anywhere. | The spec names the tools and the transports but not the result shape, the toolset names, or what `sect install` writes. | `crates/sect-mcp`, `crates/sect-cli/src/install.rs` | Proposed (milestone 7) |
| 17 | B.5 index layout | `fingerprints.json` holds, per file, size and mtime alongside the blake3 (so unchanged files are not re-hashed) and, per tracked directory, the mtime (so additions and removals are noticed without a walk); it is written one entry per line. `docs.jsonl` (the parse cache) sits next to it. | Spec B.5 lists blake3 per file only; the stat pass needs the other fields to hit its budget. | `crates/sect-index/src/lib.rs` | Proposed (milestone 6) |
| 18 | B.6 freshness | State the stat-pass budget per platform: under 10 ms for 10k files holds on Linux ext4; on Windows NTFS a cached stat costs about 18 µs whichever API is used, so the same pass takes about 70 ms. Record the threshold between a synchronous and a background refresh (20 changed files, `SECT_SYNC_LIMIT`) and that a rebuild inherits the index's embedding setting. | The spec's number is platform-dependent; saying so avoids a false promise on Windows. | `eval/results/m6.md`, decisions #36 | Proposed (milestone 6) |
| 15 | B.3 abstention | State the confidence floor: abstain when the fraction of query content terms present in the top hit is under 0.34 and its cosine is under 0.30, or when the cosine is under 0.28 regardless of overlap; a pinned hit (citation or definition) never abstains. | The spec says "when nothing exceeds the confidence floor" without defining one. These values were calibrated on the fixture with potion-retrieval-32M (decisions #35); they will need re-calibration per embedding model. | `crates/sect-rank/src/lib.rs` | Proposed (milestone 5) |
| 16 | E.1 metrics | For search-based as-of questions, exact-match means the Expression served for the expected Work equals the expected one; rank order among Works is scored as retrieval, not as the as-of guarantee. | A notice that amends a section can legitimately outrank the section for a query about the change; the structural guarantee is which text of the section is served on the date. | `eval/eval_m5.py`, `proto/sect_proto/evaluate.py` | Proposed (milestone 5) |
| 7 | B.4 fusion / rerank | Define the score scale for the signal table: RRF normalized so that rank 1 in both lists equals 1.0; title/path match is +0.10 scaled by the fraction of query content words matched; the adaptive x2 lexical weight applies only when the matched defined term covers at least half of the query's content words. | Without a defined scale the flat +0.10 boosts and the x2 weight swamped the fused score on the fixture and pushed the correct section out of the top 5 (`docs/decisions.md` #20). | `proto/sect_proto/index.py` | Proposed (milestone 0) |
